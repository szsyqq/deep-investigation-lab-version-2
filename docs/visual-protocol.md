# 视觉表达协议

## 决策顺序

每个候选视觉单元按以下顺序处理：

1. 提取 `editorialClaim`：正文要证明什么；
2. 提取 `readerTakeaway`：读者三秒后应理解什么；
3. 列出证据 ID 和数据口径；
4. 判断视觉是否比简洁正文更有效；
5. 识别关系类型；
6. 选择表达模式；
7. 最后选择组件；
8. 校验标题、注释、来源和移动端。

## 关系到模式

| 关系 | 首选模式 | 可用组件 | 禁止 |
| --- | --- | --- | --- |
| 领先指标与结果背离 | contradiction | 对照卡、带注释双趋势、因果链 | 两张无关联图 |
| 多环节传导 | causality | Story Flow、因果树 | 普通表格 |
| 同口径对象比较 | comparison | 镜像条、斜率图、紧凑表 | 雷达图堆指标 |
| 连续时间变化 | trend | 折线、柱线组合 | 截断轴误导 |
| 事件阶段与转折 | timeline | 带结论时间线 | 只列日期 |
| 风险概率与影响 | risk | 风险矩阵、情景卡 | 无概率依据的精确预测 |
| 关系不清或证据不足 | prose-only | 正文、短结论框 | 强行图表 |

## 图表合同

每个视觉计划必须包含：

- `claimId`
- `pattern`
- `component`
- `title`：表达结论，不写“数据情况”
- `readerTakeaway`
- `evidenceIds`
- `data`
- `sourceNote`
- `whyThisForm`
- `doNotUse`

图表组件不得直接读取其他报告的 DOM、全局变量或硬编码 ID。一个报告的错误不能影响另一个报告。

## 文字阶段的图表占位

完整文字稿不需要等待成图。只要某个视觉能够显著降低理解成本，就在 `draft.md` 的准确插入位置加入统一图表规划框，写明：

- 图表编号和视觉类型；
- 插入位置；
- 画面内容；
- 要说明的编辑问题；
- 证据编号和数据口径；
- 不采用的误导性形式；
- 当前制作状态。

图表规划框使用Markdown引用块，便于分析师在文字底稿中阅读；共享网页编译器忽略引用块，因此“标出位置”不会自动变成网站发布或造成重复图表。

规划框必须与 `visual-plan.json` 使用同一编号。只有完成视觉制作并获准进入预览后，才把编号加入 `publication.json.sections[].visualIds`。
