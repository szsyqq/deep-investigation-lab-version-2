# V1 只读审计结论

审计对象：`szsyqq/DeepInvestigationLab` 默认分支的公开快照。

观察到：

- 正式门户下有 21 个报告入口；
- 仓库内约有 232 个 HTML 文件，包含正式页、底稿页、查重页和大量版本归档；
- 报告正文、文章样式和图表实现主要存在于单篇 HTML 内；
- 公共 UI 由 `portal/global.js` 和 `portal/global.css` 注入，但文章结构和视觉组件没有统一数据合同；
- 存在多批修复、注入、统一和清理脚本，说明跨文章结构差异已产生较高维护成本；
- 旧方法论要求“每章至少一张可视化”，容易诱发不必要图表，与“无依据宁删图”的规则存在张力。

V2 对应决策：

- 不迁移旧报告文件，不写入 V1；
- 报告内容与网站框架分离；
- 图表从正文 HTML 中分离为视觉计划；
- 删除强制图表数量要求；
- 通过报告级数据隔离防止修复扩散；
- 修改先分类，再决定局部更新或结构重写。
