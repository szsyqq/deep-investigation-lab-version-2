# Deep Investigation Lab V2 报告生产协议

## 目标

系统接受一个自然语言调查任务，完成研究、初稿、视觉编辑、审核、人工修改、内部试读和正式发布。图表只是报告生产中的一个阶段；核心产物始终是一篇证据可靠、结构连贯、可以持续修改的完整报告。

质量优先级固定如下：

1. **准确程度与专业性是首要考核。** 数字、引语、事件、比较和结论边界必须来自可访问、可追溯的来源；不得编造、静默外推或把推断写成事实。
2. **可读性、易读性和读者吸引力是重要考核。** 通过事实选择、因果顺序、通俗解释、人物行动和真实反差实现，不得以牺牲准确性换取故事性。
3. 证据不足但好看的段落不能通过；来源齐全却只是数据堆积的段落也必须重写。

## 七阶段流程

### 1. 接收任务与识别路线

系统判断研究最终指向：

- `entity`：公司、机构、人物、产品等有清晰边界的主体；
- `topic`：行业、政策、事件、趋势或跨主体社会问题。

完成 `brief.json`，记录用户任务、核心问题、范围、排除项、时间边界、子问题和反证条件。此时不写结论。

### 2. 讨论团与迭代研究

讨论团由六种编辑视角组成：主编、行业分析师、调查研究员、反方审稿人、数据编辑和读者代表。它不是为了制造形式，而是从读者需求、市场关注、争议、历史和反证角度形成研究问题。

产出：

- `discussion.md`：讨论结论和下一轮问题；
- `research-notes.md`：每轮新发现、冲突和后续调查方向；
- `sources/`：来源底稿；
- `working-drafts/`：按阶段保存的文字、图表、图片与预览样稿；
- `evidence-ledger.json`：结构化证据账本；
- `workflow-state.json.researchLoops`：机器可读的研究循环状态。

研究允许反复返回。发现需要比较同行、补充历史、寻找第三方验证或检验替代解释时，进入下一轮，而不是直接写文章。

第一轮有效资料收集后、确定提纲前，必须完成一次“问题蒸馏”：

1. **读者视角**：普通但理性的读者最需要解释什么，什么事实真正出人意料；
2. **市场或系统视角**：主流判断依赖哪些假设，哪些驱动可能只是基数、周期或已被定价；
3. **争议与反证视角**：公开说法与结果之间有什么裂缝，什么证据会推翻正在形成的解释。

三种视角是分析镜头，不是三个真实、独立的信息源。每条观察必须标为 `verified`、`inference`、`lead` 或 `unknown`；其中事实与推断都要绑定证据编号，未核实数字和动机只能进入下一轮研究任务。

三轮材料最终蒸馏成3—5个核心追问。每个追问写明读者价值、事实张力、现有证据、证据缺口、反证条件和可回答状态。评估的目的不是确认已有观点，也不是挑选最好写的角度。追问暂时不可回答并不意味着不重要，但证据补齐前不能升级为章节结论。

### 3. 报告框架与底稿

研究充分后形成：

- `claim-map.json`：事实、分析、待核实和预测；
- `outline.md`：核心论点、章节职责、证据编号和章节之间的关系。

目录不是业务维度清单。每一章只能承担一个明确的论证职责。

### 4. 文字初稿

在 `draft.md` 中形成一篇以文字为主、可以独立阅读的完整文章。初稿应当连贯、篇幅充分，并区分事实和判断。

如果写作暴露出证据不足，返回第二阶段；如果新材料改变论点，先更新框架，再重写正文。禁止用模糊语言填补证据空白。

### 5. 图表与视觉编辑

系统从初稿提取每个候选视觉的编辑主张、读者应理解的结论和证据，再判断是否需要视觉表达。

顺序是：

```text
正文主张 → 证据 → 关系类型 → 是否需要视觉 → 表达模式 → 具体组件
```

视觉可以是观点图、数据图、时间线、关系图、地图、数据卡，也可以是 `prose-only`。图表不能只是把正文数字重新画一遍。

### 6. 审核与人工修改

机器审核写入 `review.md`，至少覆盖：

1. 来源是否可访问、事实是否可追溯、数字与引语是否准确；
2. 推断边界、比较口径、反方观点和专业解释是否成立；
3. 章节职责、叙事顺序、可读性、易读性和读者吸引力；
4. 图表必要性、来源映射和移动端表现。

审核按上述顺序执行。准确性未通过时，不得以语言流畅、故事精彩或视觉效果抵消。

分析师提出意见后，系统先判断：

- `evidence-update`：事实或来源更新；
- `local-rewrite`：局部表达调整；
- `structural-revision`：章节职责或顺序变化；
- `full-rewrite`：核心问题或中心论点变化。

修改记录进入 `revisions.md` 和 `editorial-state.json`。任何修改都要重新融入上下文，不能把新内容生硬附加到旧稿。

每次分析师作出实质纠正后，系统在同一轮任务中自动执行经验学习，不要求分析师另行触发：

1. 保存原问题、最终决定、理由、适用范围和来源报告；
2. 区分单篇选择、候选模式、共享编辑规则和共享框架规则；
3. 明确声明“以后每篇”“所有页面”“统一使用”的规则立即提升；其他写作偏好在不同章节或报告出现两次后提升；
4. 写作与研究判断进入深度调查技能参考，确定性流程进入共享协议或框架日志；
5. 确定性规则补充自动测试，判断性规则补充正反案例；
6. 下一篇真实报告作为前向验证；同类问题再次发生时，修改共享规则而不是继续打单篇补丁。

### 7. 内部预览与正式发布

报告先进入 `internal-preview`。内部页面显示版本、试读标签、待解决问题、分析师确认状态和更新时间。

只有在分析师明确同意，且研究校验、测试和网站构建通过后，才能改为 `approved` 或 `published` 并进入正式主页面。

## 每篇报告的底稿目录

```text
content/reports/<slug>/
├── brief.json
├── workflow-state.json
├── discussion.md
├── research-notes.md
├── sources/
│   ├── primary/
│   ├── secondary/
│   └── notes/
├── working-drafts/
│   ├── 01-intake/
│   ├── 02-research/
│   ├── 03-outline/
│   ├── 04-prose/
│   ├── 05-visuals/
│   ├── 06-review/
│   └── 07-preview/
├── versions/          可快速恢复的报告级版本
├── evidence-ledger.json
├── claim-map.json
├── outline.md
├── draft.md
├── visual-plan.json
├── review.md
├── revisions.md
├── editorial-state.json
└── publication.json
```

Markdown 文件服务分析师阅读和编辑，JSON 文件服务程序校验、状态管理和网页渲染。

### 底稿保存规则

1. 每篇报告只在自己的 `content/reports/<slug>/` 下保存底稿，不与其他报告共用临时目录。
2. 一手文件、二手资料和检索笔记分别进入 `sources/primary/`、`sources/secondary/` 和 `sources/notes/`。
3. 受版权保护的新闻和研究报告原则上保存链接、元数据、必要摘录与分析笔记，不整篇复制。
4. 每份来源底稿标明证据编号、原始链接、访问日期、可支持的事实及局限。
5. 每个工作阶段的文字和视觉样稿进入对应的 `working-drafts/` 子目录。新版本另存，不覆盖上一阶段。
6. 图片和图表底稿必须保留原始数据、编辑主张、版权或授权信息，以及最终是否采用的决定。

### 版本与恢复

每次实质修改前保存报告级版本：

```bash
npm run research:snapshot -- <slug> "修改说明"
```

快照保存在 `versions/<版本号>/`，包含可编辑报告文件、SHA-256校验值、创建时间和修改说明。来源原件、阶段样稿和既有版本不重复复制。

需要恢复时：

```bash
npm run research:restore -- <slug> <版本号> --confirm
```

恢复程序会先自动保存当前状态作为安全版本，再覆盖所选版本中记录的文件；不会删除后来新增的来源底稿、阶段样稿或其他版本。

## 发布门槛

- 关键事实绑定证据编号；
- 反证和不确定性已经说明；
- 初稿是完整文章，不是片段拼接；
- 视觉服务于主张并可追溯；
- 相似性、重复、事实和结构检查完成；
- 分析师明确批准；
- `npm run research:validate`、`npm test` 和生产构建通过。

## 写作门槛

进入完整正文前，每章必须在提纲中回答：

- 本章的准确问题；
- 核心结论及作用机制；
- 支持证据编号；
- 反证、替代解释或披露缺口；
- 当前证据允许得出的最窄结论；
- 与前后章节的逻辑关系。

缺少其中任何一项时，返回研究或提纲阶段。新闻人物、投资者持仓、文学化表达和泛泛的不确定性不能替代证据与机制。

流程不设置固定字数、章节数、来源数量或图表数量。研究充分性取决于核心追问、机制、反证和重要不确定性是否得到覆盖；视觉仍按理解成本决定，不按篇章配额决定。
