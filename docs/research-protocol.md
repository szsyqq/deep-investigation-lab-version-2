# 研究协议

## 1. 识别任务

先判断请求的主要对象。

- `entity`：核心问题围绕一个可识别主体展开。研究维度包括身份与边界、业务或行为、资金与结果、治理与关系、技术或能力、外部验证、争议与反证。
- `topic`：核心问题围绕一个跨主体议题展开。研究维度包括定义与边界、时间演化、参与者与利益、数据规模、政策环境、机制、受影响群体、争议与反证。

主体研究可包含行业背景，话题研究也可包含关键主体；分类取决于最终问题指向。

## 2. 研究前置

创建 `brief.json`，写清：

- 用户原始请求；
- 研究类型、范围、时间点；
- 核心问题与子问题；
- 纳入与排除范围；
- 可能推翻初步假设的反证条件。

不要在这一阶段写结论。

## 3. 证据搜集

按优先级使用：

1. 法律、监管、交易所和政府原始文件；
2. 公司财报、公告、官网与正式演讲；
3. 学术论文、行业标准和权威数据库；
4. 高质量新闻机构；
5. 专业人士或相关方公开陈述；
6. 社交平台与论坛，仅作线索，不单独支撑关键结论。

每条证据写入 `evidence-ledger.json`，记录 URL、标题、发布者、发布时间、访问时间、摘录摘要、覆盖问题、口径、可信度和冲突状态。

## 4. 编辑研讨

在写作前完成四轮检查：

- 读者：真正需要理解的核心问题是什么？
- 市场与系统：利益、激励和约束如何运作？
- 争议：不同主体如何解释同一事实？
- 反证：什么证据会推翻当前主张？

产出 `claim-map.json`。每条主张必须绑定证据，标记事实、分析或待核实。

## 5. 结构与修改

每一章节只承担一个 `sectionPurpose`。收到修改要求时先分类：

- `evidence-update`：更新数据或来源，不改变论点；
- `local-rewrite`：改善局部表达，不改变章节职责；
- `structural-revision`：新材料改变论证顺序；
- `full-rewrite`：核心问题或主要结论改变。

不得将结构性材料直接追加到正文尾部。

## 6. 发布门槛

- 关键事实全部有证据编号；
- 冲突证据已解释；
- 图表数据能追溯到证据；
- 推断与事实明确分开；
- 没有虚构采访或调查行为；
- 研究截止日期清楚；
- Visual Planner 允许并优先考虑 `prose-only`；
- 构建与研究包校验通过。
