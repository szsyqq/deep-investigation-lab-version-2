# 发布框架决策记录

这份文件记录会影响全部报道的人工决定。它不是聊天摘要，也不保存某篇文章的临时意见；只有已经确认、应由后续报道共同遵守的规则才进入这里。

## 2026-07-26：统一正式报道外壳

### 发现的问题

- 旧报道各自携带导航、法律声明和局部样式，修改一篇时可能影响其他文章。
- 不同文章的标题、导言、署名、正文宽度和试读提示不一致。
- 旧内容中的点击数字、悬浮术语和独立脚本在迁移后失效或表现突兀。
- 部分环形图、数据柱和折线图依赖旧页面脚本，迁移后失去动效。
- 首页的分类、机构、试读状态和主题标签层级不统一。

### 最终框架规则

1. 首页只负责目录、分类筛选和正式报道入口，不重复展示文章页署名组件。
2. 所有报道必须通过 `PublishedArticle`、`ArticleChrome`、`LegalFooter` 和 `EobLegalNotice` 渲染。
3. 正文外框统一为 776 像素，文字阅读栏统一为 720 像素；移动端使用共享断点。
4. 内部资料标签、试读提示、标题、导言、署名、发布日期和法律资料声明只有一个维护位置。
5. 报道内容包只保存正文、章节、兼容样式和必要数据，不保存独立导航、弹窗、页脚或脚本。
6. 导入旧报道时移除 `script`、内联事件、`data-tip` 和 `data-detail`；不再保留无法统一维护的点击数字与悬浮解释。
7. 必须由共享增强器恢复数据柱、计数器、环形图和折线描边动效，禁止每篇文章重新编写初始化脚本。
8. 每篇报道必须声明公司、产业、资本、政策、技术或社会议题之一，首页据此筛选。

### 防止再次发生

- `scripts/import-v1-reports.py` 负责迁移清洗，重复导入也不会带回旧交互。
- `tests/research-core.test.mjs` 检查内容包隔离、非法内联事件、旧提示属性以及共享外壳关键规则。
- `npm run research:validate`、`npm test`、`npm run lint` 和静态构建全部通过后才能发布。
- 以后发现跨文章问题时，先判断是否属于共享框架；若是，只修改共享层并增加回归测试，不逐篇打补丁。

## 决策升级原则

一次临时偏好不自动成为全局规则。只有满足以下条件之一才更新框架：

- 问题影响两篇或以上报道；
- 问题位于导航、法律声明、标题导言、正文容器、通用图表或发布流程；
- 人工连续多次作出相同修改；
- 问题会造成内容不可读、交互失效、法律提示不一致或发布失败。

更新顺序固定为：

```text
记录问题 → 判断共享或局部 → 修改共享组件/导入器
→ 增加回归测试 → 全量校验 → 内部预览 → 正式发布
```

## 2026-07-26：内部资料条与导航动态合并

### 人工决定

- 页面初始位置显示完整红色内部资料声明条，导航保持纸张色。
- 向下滚动超过 72 像素后，声明条收起，声明文字进入导航中央。
- 合并后的导航改为红色，返回按钮使用白色描边，目录按钮使用白底红字。
- 动效、阈值和反差按钮由 `ArticleChrome` 与全局样式统一维护，不允许单篇文章覆盖。

### 回归要求

测试必须确认滚动状态、初始声明条、紧凑状态类、红色导航及白色目录按钮仍然存在。

## 2026-07-26：紧凑导航信息减负

- 返回首页与目录在紧凑导航中统一使用白底红字，不使用描边框按钮。
- 阅读时长只在页面顶部显示，滚动后的紧凑导航不再重复。
- 内部资料声明去掉圆点，以细线方框显示。
- 当前章节只显示“导语”或“第 N 节”，不把长章节标题塞入导航。
- 页面滚动后显示右下角返回顶部按钮，点击后平滑回到页面顶部。

## 2026-07-26：首屏声明与章节分隔线

- 页面尚未滚动时，红色内部资料声明使用纯文字，不加边框；滚动并入紧凑导航后才使用细线方框。
- 署名区底线是标题区与正文之间唯一的首屏分隔线。
- 如果正文第一个直属模块是章节标题，该标题不得再次绘制顶线，也不得额外增加顶部留白。
- 正文后续章节仍保留顶线，用来区分长篇报道的章节层级。
- 以上规则由共享样式和回归测试维护，禁止在腾讯或其他单篇报道中单独修补。

## 2026-07-26：研究包驱动的内部预览

### 发现的问题

- 报告把 `publication.json.status` 设为 `internal-preview` 后，编辑部试读页仍只显示硬编码示例。
- 新报告虽完成工作流状态更新，却没有真实、可审阅的页面，导致“内部预览”只是状态字段。
- 为某篇报告单建页面会复制导航、状态提示和 Markdown 转换逻辑。

### 最终框架规则

1. `internal-preview` 与 `analyst-confirmation` 状态的研究包自动进入 `/preview` 列表。
2. `/preview/[slug]` 由 `ResearchPreviewArticle` 统一渲染 `publication.json`、`brief.json`、`editorial-state.json` 和 `draft.md`。
3. 预览页必须显示非正式发布提示、资料日期、开放问题和返回试读列表入口。
4. 单篇报告不得新增专属预览页面；旧示例页面可保留兼容，但新报告必须走动态共享路由。
5. 内部预览不改变正式发布注册表，也不代表分析师批准。

### 回归要求

- 自动化测试检查试读首页不再硬编码报告 ID、动态路由生成静态参数、共享加载器只选择允许的状态，并由统一组件展示未发布提示和开放问题。
- `npm run research:validate`、`npm test`、`npm run lint` 与生产构建通过后，预览才可交付分析师。

## 2026-07-26：完整编辑预览合同

### 人工决定

- 正文完成并经过视觉编辑后的预览，必须接近正式成品；不能只是 `draft.md` 的Markdown投影。
- “内部试读”只在页面顶部标记一次，不在标题元数据、正文或页脚重复。
- 导言是正文的一章，必须具备叙事进入、核心矛盾和首字下沉，不以短摘要代替。
- 读者界面使用连续数字脚注和文末完整来源；`E1` 等内部证据ID只保留在研究包与映射层。
- `visual-plan.json` 中进入预览的视觉必须实际渲染，包含编辑结论、数据、来源和移动端表现。
- 完整预览必须显示全部正文、图表、尾声、来源和开放问题；与正式发布的区别只在审批与可见性。

### 回归要求

- 共享加载器同时读取正文、证据账本、视觉计划和发布章节。
- 测试检查四类基础视觉组件、首字下沉、脚注来源以及单一状态标注。
- 浏览器验收必须确认页面含实际视觉节点、第一段首字样式和连续数字脚注。

## 2026-07-26：试读与正式报道禁止分叉渲染框架

### 人工纠正

- 内部试读不是一种新页面类型，只是正式报道在批准前的状态。
- 试读和正式发布必须共同使用 `PublishedArticle`、`ArticleChrome`、`LegacyVisualEnhancer` 与 `LegalFooter`。
- 结构化研究包通过共享编译层转换成与历史 `content.json` 同构的 `articleHtml`、`chapters`、`legacyStyles` 和元数据。
- 禁止再创建 `ResearchPreviewArticle`、单篇预览组件或另一套 `.research-preview-body` 排版。
- 状态差异只允许影响返回入口和顶部状态文字，不得改变正文宽度、章节层级、段落间距、脚注、图表或法律页脚。

### 回归要求

- 动态预览路由必须直接渲染 `PublishedArticle`。
- 自动化测试必须拒绝专属预览正文渲染器，并确认编译结果使用 `chap-num`、`drop-cap`、`footnotes`、`chart-box` 等既有内容合同。

## 2026-07-26：正文表现规则归入共享内容范式

### 人工纠正

- 仅共享页面外壳仍不足够。若导语标签、首字下沉和文末注记由每篇文章自行写入 HTML，新导入或重新编译时仍会丢失。
- 21 篇历史报道中，只有 7 篇正文自带 `drop-cap`；部分正文标题缺少 `chap-num`。这证明它们不能继续作为单篇内容的隐含责任。

### 最终框架规则

1. `PublishedArticle` 在渲染前统一执行内容范式归一化。
2. 第一处二级标题统一获得“导语”标识；后续标题沿用已有章节标识，没有标识时由范式层补齐。
3. 正文中既有的首字下沉标识先清理，再只对第一段统一添加一次。
4. `footnotes` 或 `data-article-notes` 从正文流抽离，由共享 `ArticleNotes` 组件置于正文之后、法律声明之前。
5. 研究包编译器只输出语义标题、普通段落和结构化注记标记，不再生成 `chap-num`、`drop-cap` 等表现性 class。
6. 本条取代上一节中“编译器必须直接输出表现性 class”的回归要求；预览和正式报道仍共用同一范式。

### 回归要求

- 对注册表中全部正式报道运行内容归一化测试，逐篇确认导语标识、唯一首段下沉和文末注记抽离。
- 共享样式维护章节标识、首字下沉与注记版式；禁止在单篇报告中修复这些规则。

## 2026-07-26：尾声、脚注链接与图表必须做视觉和交互验收

### 人工纠正

- 仅检查图表节点数量不能证明图表显示正常；必须检查实际尺寸、内容折行、溢出和移动端布局。
- 正文中的 `[数字]` 必须是可点击的脚注引用，文末条目必须显示连续编号并能返回正文。
- 文末板块统一命名为“注释与资料来源”。
- 尾声不是普通章节，所有文章都使用深色底、浅色正文和金色章节标识的共享收束样式。

### 最终框架规则

1. 内容范式将正文数字引用转换为指向 `#fnN` 的链接，并为每次引用生成稳定的返回锚点。
2. 注释条目统一生成 `fnN` 标识、十进制编号和返回正文链接；旧标题在渲染时归一化。
3. 带“尾声”或“结语”语义的末章统一进入共享 `epilogue` 容器。
4. 研究包视觉组件除结构检查外，还要在桌面端与窄屏检查尺寸、折行和溢出；反馈闭环图使用弹性布局避免节点文字被压成竖排。

### 回归要求

- 全部已发布页面逐篇检查注释标题、首条编号和正文脚注链接。
- 合同单元测试必须覆盖深色尾声、正文到注释及注释返回正文的双向锚点。

## 2026-07-26：动画属于共享报道框架

### 人工纠正

- 历史报道依靠 `reveal`、滚动观察器和 `data-w` 等属性实现渐入与图表生长，但新研究包只复用了观察器，没有完整复用动画合同。
- 图表最终尺寸直接写入行内样式会绕过滚动动画；正文是否渐入也不能由单篇 HTML 偶然决定。
- 研究包图表布局留在编译器的 `legacyStyles` 中，仍会形成新旧两套样式来源。

### 最终框架规则

1. 共享内容归一化器为章节、段落、引用块、图表和尾声统一添加 `reveal` 语义。
2. 共享视觉增强器负责滚动进入、交错延迟、柱形宽高增长、数字计数和折线绘制。
3. 研究包编译器只输出结构与 `data-w`、`data-h-pct` 等目标数据，不输出最终动画尺寸。
4. 研究包四类视觉布局全部进入共享报道样式；`legacyStyles` 只用于历史包兼容。
5. 尊重 `prefers-reduced-motion`，读者关闭动画时内容立即完整显示。

### 回归要求

- 测试必须确认正文归一化后具备 reveal 标识、编译器使用动画数据属性、研究包不再携带专属视觉 CSS。
- 浏览器验收同时检查进入视口前后的透明度、位移和柱形目标尺寸。

## 2026-07-26：试读差异集中在正文顶部审阅框

### 人工纠正

- 试读状态、待确认问题与不确定项散落在导航、正文末尾或专属组件中，会让预览再次形成另一套页面。
- 试读文章除审阅信息外，应与正式文章完全同构。

### 最终框架规则

1. 试读专属信息只允许出现在标题区之后、正文之前的 `PreviewReviewPanel`。
2. 审阅框统一包含“试读”标识、返回试读列表入口、“试读后需要确认的问题”标题，以及全部待确认判断、不确定内容和潜在问题。
3. 试读导航直接使用正式文章的 `ArticleChrome`；不得出现试读专属横幅、分类文字或返回按钮。
4. 研究包编译器通过结构化 `openQuestions` 传递问题，不把问题写入正文 HTML。
5. 删除废弃的 `research-preview-*`、`preview-chart` 和文末问题样式，防止备用预览框架复活。

### 回归要求

- 测试必须确认审阅框只由 `report.preview` 控制、编译器不生成文末问题块、正式导航不含试读分支。
- 浏览器验收必须确认试读标识只出现一次，审阅框位于第一章之前，文末不再出现待确认问题。

## 2026-07-26：正式首页使用可交互报道卡片

### 人工决定

- 正式报道目录不再使用接近普通文字列表的横向条目，统一改为具有明确边界的小卡片。
- 桌面端三列、平板两列、手机单列；卡片高度与信息层级由共享样式统一维护。
- 整张卡片都是报道链接，悬停和键盘焦点时必须通过抬升、边框、阴影与箭头位移给出一致反馈。
- 卡片必须保留报道分类、机构、试读状态、主题标签、发布时间和阅读时长，不出现开发说明。
- 首页卡片只负责发现与进入正式报道，不复制文章正文组件。

### 回归要求

- 自动测试确认目录继续由单一 `ReportDirectory` 渲染，卡片整块可点击，并具备桌面三列、移动端单列和键盘焦点反馈。
