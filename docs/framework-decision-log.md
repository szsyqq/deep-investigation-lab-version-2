# 发布框架决策记录

这份文件记录会影响全部报道的人工决定。它不是聊天摘要，也不保存某篇文章的临时意见；只有已经确认、应由后续报道共同遵守的规则才进入这里。

## 2026-07-27：研究包可直接渲染经指定的 JSON 正文

- 问题：分析师提供了结构化 JSON 主稿，要求保留其原有标题、引言、导语、章节、尾声和脚注，既有 Markdown 成稿不应再改写或替代该文本。
- 决定：共享研究预览加载器支持由报告包声明只读 `sourceJsonPath`，编译器直接解析 JSON 并通过既有文章框架渲染；图表仅由独立的章节插入配置添加，不能改动 JSON 原文。用于 GitHub Pages 的报告须将已确认的 JSON 原件导入报告包的 `sources/notes/article.json`，以相对路径读取；外部绝对路径不得作为公开构建的唯一来源。
- 适用边界：只对明确声明 JSON 为主稿的报告生效；默认研究包仍使用自身 `draft.md`，原始 JSON 不被写回或修改。
- 验证：回归测试检查加载和编译路径；预览页面核验原文标题、章节、尾声、31条脚注和配置图表均存在。

## 2026-07-27：内部预览路由必须接受新研究包参数

- 问题：试读目录可以读取 `internal-preview` 研究包，但动态详情页在开发预览中对新 slug 返回 404，导致已制作图表无法被分析师实际审阅。
- 决定：共享 `app/preview/[slug]` 路由保留静态生成提示，同时将 `dynamicParams` 设为 `true`；路由继续由 `getPreviewReport` 校验报告状态，而不为单篇报告创建固定页面。
- 适用边界：仅适用于内部研究包预览的共享动态路由；正式发布路由和不存在、未处于预览状态的报告仍由加载器拒绝。
- 验证：回归测试检查路由参数策略；运行时请求泡泡玛特预览页并核验八张图表、尾声与注释来源。

## 2026-07-27：文字底稿的图表规划标记不得进入网站正文

- 问题：标准图表规划块使用 Markdown 引用格式；其中仅含 `>` 的空白分隔行未被共享编译器过滤，导致网站正文出现多余的 `>` 符号。
- 决定：研究报告编译器过滤所有以 `>` 开头的工作流标记行，而不是只过滤 `> ` 开头的文字行。图表仍由 `publication.json` 的视觉编排在对应章节后渲染。
- 适用边界：仅针对研究包 `draft.md` 的工作流引用块，不移除正式报道内容中由内容合同明确支持的读者引用。
- 验证：回归测试断言完整的引用标记过滤规则；运行时预览页不得输出孤立的 `>` 段落。

## 2026-07-26：统一正式报道外壳

### 发现的问题

- 旧报道各自携带导航、法律声明和局部样式，修改一篇时可能影响其他文章。
- 不同文章的标题、导言、署名、正文宽度和试读提示不一致。
- 旧内容中的点击数字、悬浮术语和独立脚本在迁移后失效或表现突兀。
- 部分环形图、数据柱和折线图依赖旧页面脚本，迁移后失去动效。
- 首页的分类、机构、试读状态和主题标签层级不统一。

### 最终框架规则

1. 首页只负责目录、分类筛选和正式报道入口，不重复展示文章页署名组件。
2. 所有报道必须通过 `PublishedArticle`、`ArticleChrome`、`LegalFooter` 和 `EobLegalNotice` 渲染。
3. 正文外框统一为 776 像素，文字阅读栏统一为 720 像素；移动端使用共享断点。
4. 内部资料标签、试读提示、标题、导言、署名、发布日期和法律资料声明只有一个维护位置。
5. 报道内容包只保存正文、章节、兼容样式和必要数据，不保存独立导航、弹窗、页脚或脚本。
6. 导入旧报道时移除 `script`、内联事件、`data-tip` 和 `data-detail`；不再保留无法统一维护的点击数字与悬浮解释。
7. 必须由共享增强器恢复数据柱、计数器、环形图和折线描边动效，禁止每篇文章重新编写初始化脚本。
8. 每篇报道必须声明公司、产业、资本、政策、技术或社会议题之一，首页据此筛选。

### 防止再次发生

- `scripts/import-v1-reports.py` 负责迁移清洗，重复导入也不会带回旧交互。
- `tests/research-core.test.mjs` 检查内容包隔离、非法内联事件、旧提示属性以及共享外壳关键规则。
- `npm run research:validate`、`npm test`、`npm run lint` 和静态构建全部通过后才能发布。
- 以后发现跨文章问题时，先判断是否属于共享框架；若是，只修改共享层并增加回归测试，不逐篇打补丁。

## 决策升级原则

一次临时偏好不自动成为全局规则。只有满足以下条件之一才更新框架：

- 问题影响两篇或以上报道；
- 问题位于导航、法律声明、标题导言、正文容器、通用图表或发布流程；
- 人工连续多次作出相同修改；
- 问题会造成内容不可读、交互失效、法律提示不一致或发布失败。

更新顺序固定为：

```text
记录问题 → 判断共享或局部 → 修改共享组件/导入器
→ 增加回归测试 → 全量校验 → 内部预览 → 正式发布
```

- 动效、阈值和反差按钮由 `ArticleChrome` 与全局样式统一维护，不允许单篇文章覆盖。

### 回归要求

测试必须确认滚动状态、初始声明条、紧凑状态类、红色导航及白色目录按钮仍然存在。

## 2026-07-26：紧凑导航信息减负

- 返回首页与目录在紧凑导航中统一使用白底红字，不使用描边框按钮。
- 阅读时长只在页面顶部显示，滚动后的紧凑导航不再重复。
- 内部资料声明去掉圆点，以细线方框显示。
- 当前章节只显示“导语”或“第 N 节”，不把长章节标题塞入导航。
- 页面滚动后显示右下角返回顶部按钮，点击后平滑回到页面顶部。

## 2026-07-26：首屏声明与章节分隔线

- 页面尚未滚动时，红色内部资料声明使用纯文字，不加边框；滚动并入紧凑导航后才使用细线方框。
- 署名区底线是标题区与正文之间唯一的首屏分隔线。
- 如果正文第一个直属模块是章节标题，该标题不得再次绘制顶线，也不得额外增加顶部留白。
- 正文后续章节仍保留顶线，用来区分长篇报道的章节层级。
- 以上规则由共享样式和回归测试维护，禁止在腾讯或其他单篇报道中单独修补。

## 2026-07-26：研究包驱动的内部预览

### 发现的问题

- 报告把 `publication.json.status` 设为 `internal-preview` 后，编辑部试读页仍只显示硬编码示例。
- 新报告虽完成工作流状态更新，却没有真实、可审阅的页面，导致“内部预览”只是状态字段。
- 为某篇报告单建页面会复制导航、状态提示和 Markdown 转换逻辑。

### 最终框架规则

1. `internal-preview` 与 `analyst-confirmation` 状态的研究包自动进入 `/preview` 列表。
2. `/preview/[slug]` 由 `ResearchPreviewArticle` 统一渲染 `publication.json`、`brief.json`、`editorial-state.json` 和 `draft.md`。
3. 预览页必须显示非正式发布提示、资料日期、开放问题和返回试读列表入口。
4. 单篇报告不得新增专属预览页面；旧示例页面可保留兼容，但新报告必须走动态共享路由。
5. 内部预览不改变正式发布注册表，也不代表分析师批准。

### 回归要求

- 自动化测试检查试读首页不再硬编码报告 ID、动态路由生成静态参数、共享加载器只选择允许的状态，并由统一组件展示未发布提示和开放问题。
- `npm run research:validate`、`npm test`、`npm run lint` 与生产构建通过后，预览才可交付分析师。

## 2026-07-26：完整编辑预览合同

### 人工决定

- 正文完成并经过视觉编辑后的预览，必须接近正式成品；不能只是 `draft.md` 的Markdown投影。
- “内部试读”只在页面顶部标记一次，不在标题元数据、正文或页脚重复。
- 导言是正文的一章，必须具备叙事进入、核心矛盾和首字下沉，不以短摘要代替。
- 读者界面使用连续数字脚注和文末完整来源；`E1` 等内部证据ID只保留在研究包与映射层。
- `visual-plan.json` 中进入预览的视觉必须实际渲染，包含编辑结论、数据、来源和移动端表现。
- 完整预览必须显示全部正文、图表、尾声、来源和开放问题；与正式发布的区别只在审批与可见性。

### 回归要求

- 共享加载器同时读取正文、证据账本、视觉计划和发布章节。
- 测试检查四类基础视觉组件、首字下沉、脚注来源以及单一状态标注。
- 浏览器验收必须确认页面含实际视觉节点、第一段首字样式和连续数字脚注。

## 2026-07-26：试读与正式报道禁止分叉渲染框架

### 人工纠正

- 内部试读不是一种新页面类型，只是正式报道在批准前的状态。
- 试读和正式发布必须共同使用 `PublishedArticle`、`ArticleChrome`、`LegacyVisualEnhancer` 与 `LegalFooter`。
- 结构化研究包通过共享编译层转换成与历史 `content.json` 同构的 `articleHtml`、`chapters`、`legacyStyles` 和元数据。
- 禁止再创建 `ResearchPreviewArticle`、单篇预览组件或另一套 `.research-preview-body` 排版。
- 状态差异只允许影响返回入口和顶部状态文字，不得改变正文宽度、章节层级、段落间距、脚注、图表或法律页脚。

### 回归要求

- 动态预览路由必须直接渲染 `PublishedArticle`。
- 自动化测试必须拒绝专属预览正文渲染器，并确认编译结果使用 `chap-num`、`drop-cap`、`footnotes`、`chart-box` 等既有内容合同。

## 2026-07-26：正文表现规则归入共享内容范式

### 人工纠正

- 仅共享页面外壳仍不足够。若导语标签、首字下沉和文末注记由每篇文章自行写入 HTML，新导入或重新编译时仍会丢失。
- 21 篇历史报道中，只有 7 篇正文自带 `drop-cap`；部分正文标题缺少 `chap-num`。这证明它们不能继续作为单篇内容的隐含责任。

### 最终框架规则

1. `PublishedArticle` 在渲染前统一执行内容范式归一化。
2. 第一处二级标题统一获得“导语”标识；后续标题沿用已有章节标识，没有标识时由范式层补齐。
3. 正文中既有的首字下沉标识先清理，再只对第一段统一添加一次。
4. `footnotes` 或 `data-article-notes` 从正文流抽离，由共享 `ArticleNotes` 组件置于正文之后、法律声明之前。
5. 研究包编译器只输出语义标题、普通段落和结构化注记标记，不再生成 `chap-num`、`drop-cap` 等表现性 class。
6. 本条取代上一节中“编译器必须直接输出表现性 class”的回归要求；预览和正式报道仍共用同一范式。

### 回归要求

- 对注册表中全部正式报道运行内容归一化测试，逐篇确认导语标识、唯一首段下沉和文末注记抽离。
- 共享样式维护章节标识、首字下沉与注记版式；禁止在单篇报告中修复这些规则。

## 2026-07-26：尾声、脚注链接与图表必须做视觉和交互验收

### 人工纠正

- 仅检查图表节点数量不能证明图表显示正常；必须检查实际尺寸、内容折行、溢出和移动端布局。
- 正文中的 `[数字]` 必须是可点击的脚注引用，文末条目必须显示连续编号并能返回正文。
- 文末板块统一命名为“注释与资料来源”。
- 尾声不是普通章节，所有文章都使用深色底、浅色正文和金色章节标识的共享收束样式。

### 最终框架规则

1. 内容范式将正文数字引用转换为指向 `#fnN` 的链接，并为每次引用生成稳定的返回锚点。
2. 注释条目统一生成 `fnN` 标识、十进制编号和返回正文链接；旧标题在渲染时归一化。
3. 带“尾声”或“结语”语义的末章统一进入共享 `epilogue` 容器。
4. 研究包视觉组件除结构检查外，还要在桌面端与窄屏检查尺寸、折行和溢出；反馈闭环图使用弹性布局避免节点文字被压成竖排。

### 回归要求

- 全部已发布页面逐篇检查注释标题、首条编号和正文脚注链接。
- 合同单元测试必须覆盖深色尾声、正文到注释及注释返回正文的双向锚点。

## 2026-07-26：动画属于共享报道框架

### 人工纠正

- 历史报道依靠 `reveal`、滚动观察器和 `data-w` 等属性实现渐入与图表生长，但新研究包只复用了观察器，没有完整复用动画合同。
- 图表最终尺寸直接写入行内样式会绕过滚动动画；正文是否渐入也不能由单篇 HTML 偶然决定。
- 研究包图表布局留在编译器的 `legacyStyles` 中，仍会形成新旧两套样式来源。

### 最终框架规则

1. 共享内容归一化器为章节、段落、引用块、图表和尾声统一添加 `reveal` 语义。
2. 共享视觉增强器负责滚动进入、交错延迟、柱形宽高增长、数字计数和折线绘制。
3. 研究包编译器只输出结构与 `data-w`、`data-h-pct` 等目标数据，不输出最终动画尺寸。
4. 研究包四类视觉布局全部进入共享报道样式；`legacyStyles` 只用于历史包兼容。
5. 尊重 `prefers-reduced-motion`，读者关闭动画时内容立即完整显示。

### 回归要求

- 测试必须确认正文归一化后具备 reveal 标识、编译器使用动画数据属性、研究包不再携带专属视觉 CSS。
- 浏览器验收同时检查进入视口前后的透明度、位移和柱形目标尺寸。

## 2026-07-26：试读差异集中在正文顶部审阅框

### 人工纠正

- 试读状态、待确认问题与不确定项散落在导航、正文末尾或专属组件中，会让预览再次形成另一套页面。
- 试读文章除审阅信息外，应与正式文章完全同构。

### 最终框架规则

1. 试读专属信息只允许出现在标题区之后、正文之前的 `PreviewReviewPanel`。
2. 审阅框统一包含“试读”标识、返回试读列表入口、“试读后需要确认的问题”标题，以及全部待确认判断、不确定内容和潜在问题。
3. 试读导航直接使用正式文章的 `ArticleChrome`；不得出现试读专属横幅、分类文字或返回按钮。
4. 研究包编译器通过结构化 `openQuestions` 传递问题，不把问题写入正文 HTML。
5. 删除废弃的 `research-preview-*`、`preview-chart` 和文末问题样式，防止备用预览框架复活。

### 回归要求

- 测试必须确认审阅框只由 `report.preview` 控制、编译器不生成文末问题块、正式导航不含试读分支。
- 浏览器验收必须确认试读标识只出现一次，审阅框位于第一章之前，文末不再出现待确认问题。

## 2026-07-26：正式首页使用可交互报道卡片

### 人工决定

- 正式报道目录不再使用接近普通文字列表的横向条目，统一改为具有明确边界的小卡片。
- 桌面端三列、平板两列、手机单列；卡片高度与信息层级由共享样式统一维护。
- 整张卡片都是报道链接，悬停和键盘焦点时必须通过抬升、边框、阴影与箭头位移给出一致反馈。
- 卡片必须保留报道分类、机构、试读状态、主题标签、发布时间和阅读时长，不出现开发说明。
- 首页卡片只负责发现与进入正式报道，不复制文章正文组件。

### 回归要求

- 自动测试确认目录继续由单一 `ReportDirectory` 渲染，卡片整块可点击，并具备桌面三列、移动端单列和键盘焦点反馈。

## 2026-07-26：报道卡片保持单列阅读节奏

### 人工纠正

- “卡片形式”指每篇报道拥有明确边界和交互反馈，不代表采用多列宫格。
- 正式首页恢复一排一篇的单列节奏；桌面端在卡片内部组织分类、标题摘要和发布日期，窄屏再纵向折叠。

## 2026-07-26：“引言”是标题摘要，“序言”是正文开篇

- 正文的开篇章节称为“序言”。

### 最终框架规则

1. `publication.json.deck` 和页面标题下方摘要统一承担“引言”职责。
2. 研究正文使用 `## 序言：标题`，编译器输出“序言”章节标签。

## 2026-07-26：引言与序言采用两层调查开场

### 人工纠正

- “简短”不能被理解为只有一句点题文字。
- 既有优秀报道通常由标题下方高密度摘要和正文故事开篇共同完成吸引、交代和提出问题。

### 最终框架规则

1. 引言位于标题下方，用两至四个关键事实或数字压缩全文最重要的冲突和阅读价值。
2. 序言使用具体场景、人物、时间或代表性产品形成故事入口，并由现场自然过渡到核心调查问题。
3. 序言可以适度提示后文将检验的方向，但不逐章罗列，也不提前写完结论。
4. 引言和序言不得机械重复同一组事实；序言扩写后，应同步检查第一章并删除重复段落。
5. 篇幅由故事完整性决定，不设机械字数上限；专业、克制和信息密度继续优先于煽情。

## 2026-07-26：争议分析先给出可测量事实，投资收益使用完整口径

### 人工纠正

- 先写“稀缺性不等于需求”等解释，再补商品价格，会让个人判断冒充事实并破坏叙事顺序。
- 持仓市值不能回答投资者赚了多少钱；缺少成本和权利金时计算总收益会制造虚假精度。
- 面向非专业读者解释金融工具时，应先说明经济承诺、可能结果和风险，再给出术语。

### 最终框架规则

1. 争议型章节先写明具体对象、起止时间、起始值、结束值和可比口径，再列替代解释。
2. 同时发生的价格与供给变化可以并置，但缺少连续序列时不得画成已证明的相关性或因果关系。
3. 投资收益只计算具备数量、成本基础和统一估值日的交易；必须标明已实现或未实现、覆盖比例、费用和未披露项目。
4. 只有持仓数量和当前价格时，只能计算市值，不能称为盈利。
5. 期权等专业工具先翻译为普通读者可理解的经济安排，再说明术语和下行风险。

### 来源与适用边界

- 来源：泡泡玛特报告D20与R18；该意见延续此前D18关于“事实和机制替代空泛判断”的纠正，因此提升为共享编辑规则。
- 不要求所有章节机械使用数字开篇；仅在价格、收益、需求、市场变化等可测量争议中强制事实先行。

### 回归要求

- 深度调查写作合同保留“可测量事实先行”和“市值不得代替盈利”的硬性规则。

## 2026-07-26：总结必须产生信息增量，全文按因果段落推进

### 人工纠正

- “现阶段能写下的不是……”等句子只是把前文换一种说法，没有形成新的综合结论。
- 局部修正不能解决全文由孤立短句、重复判断和元叙述造成的碎片化。

### 最终框架规则

1. 总结只有在压缩两项以上发现并导出新结论时保留；复述上一段的总结直接删除。
2. “本文要说的是”“正确结论不是”“这意味着”等元叙述不得承担段落衔接。
3. 孤立的铺垫句与其证据合并；段落必须新增事实、解释机制、检验替代解释或推进叙事。
4. 修改一个碎片化问题时，对全文执行同类句式和段落审计，而不是只替换被指出的句子。
5. 必要的短句可以用于场景节奏或结尾收束，但不能连续代替事实和因果。

### 来源与适用边界

- 来源：泡泡玛特报告D21与R19；该规则延续D18和D20关于事实密度、因果叙事的多次纠正，提升为共享编辑规则。

### 回归要求

- 深度调查写作合同必须保留“无信息增量的元总结删除”和“段落因果连接”规则。

## 2026-07-27：人物故事只由可验证行动推进，无效的缺失说明应删除

### 人工纠正

- “最初不买，因为他不确定需求能持续多久”把公开疑问直接解释成投资者的内心动机，超出了证据能够支持的范围。
- 公开资料不能计算整个仓位利润，并不意味着正文需要长篇解释不可计算的原因；如果这个答案不影响核心判断，说明本身就是阅读负担。
- 文章的题材和观点可以成立，但若事实只是并列陈述，仍然缺少财经调查应有的故事推进。

### 最终框架规则

1. 人物叙事优先使用可核查的场景、原话、行动、日期、文件和结果；除非本人明确说明，不把时间先后写成心理因果。
2. “他为何改变主意”等问题若没有直接证据，正文应呈现改变前后的事实，并明确证据边界，不代替人物补写动机。
3. 缺失数据只有在会显著改变结论、口径或风险判断时才解释；与核心问题无关的不可计算项直接删除。
4. 故事性由事件的时间顺序、行动与后果、事实反差和逐层揭示构成，不能依赖文学化过渡、空泛判断或未经证实的心理描述。
5. 学习财经媒体的是事实组织、段落节奏和证据归因，不模仿具体句子，也不以“媒体风格”降低证据标准。

### 来源与适用边界

- 来源：泡泡玛特报告D22与R20；该纠正延续D18、D20、D21对事实密度、因果叙事和信息增量的要求，因此提升为共享编辑规则。
- 对有本人访谈、书信、演讲或正式文件直接说明动机的情况，可以归因式呈现，但必须清楚标注来源。

### 回归要求

- 深度调查写作合同保留“可验证行动替代心理揣测”和“无关的缺失数据说明删除”两项规则。

## 2026-07-27：资料收集后必须经过多视角问题蒸馏

### 参考流程中可复用的经验

- 原流程在写作前依次采用读者、市场和争议视角，并把材料压缩为3—5个真正值得追问的问题。
- 这一阶段能够阻止“资料收集完成后直接写作”，也能避免文章只是公开来源的重新排列。
- 追问必须同时具有读者价值、事实张力和可调查的证据路径；评估过程不得只确认已有观点。

### 需要修正的旧风险

- 评估文本中的“153亿买入”“all in”“儿童是核心客群”“创始人套现代表不看好”等表述混合了市值、交易事实、推断和心理归因，不能未经核验进入正文。
- “市场共识”“社交热度下降”等判断必须说明来源与口径；单一AI扮演多个角色不等于获得多个独立来源。
- 固定8,000字、八章、七张图或三个来源渠道会把质量指标变成配额，与“图表先提取主张”和证据充分性原则冲突。

### 最终框架规则

1. 第一轮有效资料收集后、锁定提纲前，执行读者、市场或系统、争议与反证三种分析镜头。
2. 每条观察标为 `verified`、`inference`、`lead` 或 `unknown`；事实和推断绑定证据编号，线索只生成研究任务。
3. 最终蒸馏3—5个核心追问，每个问题必须记录读者价值、张力、已有证据、证据缺口、反证条件和可回答状态。
4. 暂时不可回答的问题可以保留为研究方向，但不得提前变成章节结论。
5. 不以固定字数、章节数、来源数或图表数替代研究充分性判断。

### 来源与适用边界

- 来源：原V1《报道流程》中的“评估团研讨”，以及泡泡玛特评估团四份底稿；在V2中改造为有证据标签和反证门槛的问题蒸馏流程。
- 公司报告使用“市场视角”；政策、行业或社会议题使用与资源配置有关的“系统视角”，不机械套用投资者问题。

### 回归要求

- 新报告的 `discussion.md` 模板包含三种视角和六项追问字段。
- 深度调查技能在提纲前强制读取问题蒸馏参考。

## 2026-07-27：准确性优先，可读性与吸引力不得突破证据边界

### 分析师全局要求

- 文章准确程度和专业性是主要考核：不编造数据，只依赖能够查询、访问和追溯的数据。
- 可读性、易读性和对读者的吸引力是重要考核。

### 最终框架规则

1. 质量审核按“来源可访问与事实准确—专业解释与证据边界—可读性、易读性与吸引力—视觉体验”依次进行。
2. 数字、引语、事件、比较和因果必须在来源实际支持范围内；不得静默外推、补写动机或制造虚假精度。
3. 故事性只能通过真实场景、人物行动、时间顺序、事实反差和逐层解释建立。
4. 准确性失败不能被流畅语言或视觉效果抵消；来源齐全但没有解释、难以阅读的数据堆积也不能通过。
5. 无法核实但可能重要的内容退回研究、缩窄表述、明确标注或删除，不以“可能”“据称”等模糊词掩盖证据缺口。

### 适用范围

- 适用于所有深度调查报告、内部预览和正式发布版本。

### 回归要求

- 新报告审核模板必须显示质量检查顺序和不可相互抵消的原则。
- 深度调查技能与写作合同必须明确准确性为首要门槛，并保留可读性和吸引力要求。

## 2026-07-27：成熟财经语气不靠课堂式设问或拟人化标题

### 人工纠正

- 新版事实结构已改善，但“第二场考试”“这道题”“角色能否离开货架”等表达仍显得幼稚，削弱了专业调查报道的语气。

### 最终框架规则

1. 商业分析标题优先写事实、机制或经营约束，不使用考试、闯关、输赢等课堂或游戏化框架。
2. 能用陈述句和证据推进的地方，不用口语化设问代替分析。
3. 成熟的可读性来自事件、经营含义和证据边界的顺序，而不是作者反复提醒读者“问题是什么”。

### 来源与适用边界

- 来源：泡泡玛特报告D12、D21、D24及本轮语言退回意见。
- 允许保留来自可核验引语的提问；标题在确有必要时可使用克制设问，但不得用作节奏填充。

### 回归要求

- 共享写作合同必须列出课堂式、游戏化框架和口语化设问的限制。

## 2026-07-27：图表进入内部预览前必须有真实组件和移动端验收

### 人工决定

- 分析师要求将泡泡玛特报告由图表规划阶段推进至图表输出阶段。
- 已有V5—V7具备证据、数据和编辑主张，但共享编译器尚未支持其时间线、比较表和双轨事实图组件。

### 最终框架规则

1. 图表获准进入内部预览时，必须把对应视觉ID写入 `publication.json.sections[].visualIds`，并将视觉状态改为 `approved-for-internal-preview`。
2. 每种新组件必须在共享编译器中实现，在共享样式中提供桌面端、移动端和减少动画偏好下的可读布局。
3. 图表只使用视觉计划中证据ID支持的数据；外部草稿中的数字、引语和推断未经核验不得作为图表输入。
4. 组件接入必须补充自动回归检查，确保内部预览继续通过同一文章框架渲染。

### 来源与适用边界

- 来源：泡泡玛特报告D26/R24。
- 这不要求每个规划图都立即制作；只有经编辑审核、数据完整且确实降低理解成本的图表进入预览。

### 回归要求

- 自动测试确认时间线、编辑型比较表、双轨事实图和横向排名图均由共享编译器与共享样式支持。
